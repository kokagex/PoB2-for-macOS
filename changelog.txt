VERSION[0.10.2][2026/06/06]

--- ツリー表示時の CPU 過負荷を削減し、0_4 ツリーのクラッシュを修正 / Reduce passive-tree CPU load and fix a 0_4-tree crash ---
* パッシブツリー表示時（特に「Show Node Power」／ヒートマップ）の CPU 過負荷とフリーズを解消。macOS では sg.GetTime() が秒を返すのに上流 src/ の全消費側はミリ秒前提で書かれており、(1) アイドル検出が秒スケールのため常にスロットルされず約 49% の CPU を消費、(2) CalcsTab のノードパワー再計算の協調的 yield ゲート（GetTime() - start > 100 が 100 秒の意味になる）が約 2 秒の全ツリー走査中に一度も yield せず 1 フレームでフリーズ、という 2 症状が同一原因から発生していた。GUI 境界で `_G.GetTime` を ms 正規化（×1000）する 1 箇所のラップで全消費側を一括修正（pob2_launch.lua）
* 0_4（以前）のパッシブツリーで「PassiveTreeView.lua:664: attempt to index field 'handle' (a nil value)」クラッシュを修正。これらのツリーは .dds.zst テクスチャ配列を使い macOS ポートではロードできず、ロード失敗側の分岐で handle=nil を格納してアセット不変条件（全レコードが非 nil の画像ハンドルを持つ）を破っていた。失敗時も LoadImage が常に生成する空ハンドル（data.handle）を格納するよう修正し、ロード時に nil ハンドルがあれば error する不変条件チェックを追加（src/Classes/PassiveTree.lua）
* ※Lua のみの変更。zip の再ダウンロード（再インストール）が必要です

* Fixed excessive CPU use and freezes while the passive tree is shown (especially "Show Node Power" / the heat map). On macOS sg.GetTime() returns seconds, but every upstream src/ consumer assumes milliseconds, so two symptoms shared one root cause: (1) idle detection on a seconds scale never throttled and burned ~49% CPU, and (2) the CalcsTab node-power recalc's cooperative yield gate (GetTime() - start > 100 became 100 seconds) never yielded during the ~2-second full-tree walk and froze a whole frame. Fixed all consumers with a single ms-normalizing wrap of `_G.GetTime` (×1000) at the GUI boundary (pob2_launch.lua).
* Fixed a "PassiveTreeView.lua:664: attempt to index field 'handle' (a nil value)" crash on 0_4 (and older) passive trees. Those trees use .dds.zst texture arrays the macOS port cannot load, and the failed-load branch stored handle=nil, breaking the asset invariant that every record carries a non-nil image handle. It now stores the empty handle LoadImage always creates (data.handle) even on failure, plus a load-time invariant check that errors if any record has a nil handle (src/Classes/PassiveTree.lua).
* Note: Lua-only change; requires re-downloading the zip (reinstall).

* Hid the "Find Timeless Jewel" button, which does not exist in PoE2 and overlapped the "Show Node Power" checkbox, stealing its input (src/Classes/TreeTab.lua).

* OnFrame 中に `bad argument #2 to 'LaunchSubScript' (cannot convert 'string' to 'void *')` で落ちる問題を修正。macOS の dylib バインディングが 2 引数スタブ（scriptName, luaState）のままで、PoB 本来の多引数呼び出しと型が合わず FFI チェックで即クラッシュしていた（stage4 以来の潜在バグ。サブスクリプトを使う全機能＝ビルドのインポート/エクスポート、Pastebin/pobb.in/Maxroll/poe.ninja ダウンロード、PoB Archives 類似ビルド、ツリー PoEURL 解決が起動直後やそれら操作時に落ちていた）
* dylib は再ビルド不可のため、`_G.LaunchSubScript` を pure-Lua の同期シムに差し替え（pob2_launch.lua）。スクリプトをメイン Lua state で同期実行し、結果を毎フレーム OnFrame の `DrainSubScripts()` で遅延配送（コールバック登録が呼び出し後に行われる Pattern 2 にも対応）。9 箇所の呼び出し全てを単一の choke point でカバー
* 起動時/12時間ごと/Ctrl-U の自動アップデート確認（CheckForUpdate）が同じ経路でクラッシュしていたため no-op 化。macOS ポートはアプリ内自己アップデート非対応のため実害なし
* curl 経路に接続/全体タイムアウト（CONNECTTIMEOUT 10s / TIMEOUT 30s）を追加し、ダウンロード hang を防止（Launch.lua, BuildSiteTools.lua, PoBArchivesProvider.lua, TreeTab.lua）
* 注意: ダウンロードは現状メイン state で同期実行のため、取得中は最大タイムアウト分 UI が一時停止します
* ※Lua のみの変更。zip の再ダウンロード（再インストール）が必要です

* Fixed a crash in OnFrame: `bad argument #2 to 'LaunchSubScript' (cannot convert 'string' to 'void *')`. The macOS dylib binding was still a 2-arg stub (scriptName, luaState), which mismatched PoB's multi-arg calling convention and crashed at the FFI type check (a latent bug since stage4 — every sub-script feature crashed: build import/export, Pastebin/pobb.in/Maxroll/poe.ninja downloads, PoB Archives similar builds, and tree PoEURL resolution).
* Since the dylib cannot be rebuilt, `_G.LaunchSubScript` is replaced with a pure-Lua synchronous shim (pob2_launch.lua). Scripts run synchronously in the main Lua state and results are delivered deferred via `DrainSubScripts()` each frame in OnFrame (also handles Pattern 2 callers that register their callback after the call returns). A single choke point covers all 9 call sites.
* The auto update-check (CheckForUpdate, fired at startup / every 12h / Ctrl-U) crashed via the same path, so it is now a no-op. Harmless on the macOS port, which does not support in-app self-update.
* Added connect/total timeouts (CONNECTTIMEOUT 10s / TIMEOUT 30s) to the curl paths to prevent download hangs (Launch.lua, BuildSiteTools.lua, PoBArchivesProvider.lua, TreeTab.lua).
* Note: downloads currently run synchronously in the main state, so the UI pauses for up to the timeout while fetching.
* Note: Lua-only change, but requires re-downloading the zip (reinstall).

VERSION[0.9.2][2026/06/04]

--- Metal autoreleasepool リーク修正（ツリー操作の枯渇クラッシュ解消）/ Fix Metal autoreleasepool leak (passive-tree memory-exhaustion crash) ---
* パッシブツリー操作中にメモリが急増し数分でクラッシュする問題を修正。SimpleGraphic.dylib の Metal 描画ループに per-frame autoreleasepool が無く、autorelease された Metal オブジェクト（command encoder/buffer/drawable）が毎フレーム蓄積していた（実測: ツリー操作 10 秒で +500MB → 8GB 枯渇で AMD Metal ドライバが SIGBUS）
* dylib は再ビルド不可のため、glfwPollEvents（毎フレーム先頭で呼ばれる）を interpose する注入 dylib（libpob_poolfix.dylib）を DYLD_INSERT_LIBRARIES でロードし、フレーム先頭の安全な点で pool を排出（runtime/libpob_poolfix.dylib, package/poolfix/pob_poolfix.c）
* 検証: 同一ツリー操作で MALLOC_NANO が未修正 1.0G→1.5G に対し、修正版は 512M→512M でフラット・クラッシュ無し
* ※ランチャ＋新 dylib を含むため zip の再ダウンロード（再インストール）が必要。アプリ内アップデートでは反映されません

* Fixed a crash where memory ballooned and the app died within minutes while manipulating the passive tree. SimpleGraphic.dylib's Metal render loop had no per-frame autoreleasepool, so autoreleased Metal objects (command encoder/buffer/drawable) accumulated every frame (~500MB in 10s of tree manipulation → 8GB exhaustion → AMD Metal driver SIGBUS).
* Since the dylib cannot be rebuilt, a small injected dylib (libpob_poolfix.dylib) interposes glfwPollEvents (called at the top of each frame) and drains the autorelease pool at that safe point, loaded via DYLD_INSERT_LIBRARIES.
* Verified: under identical tree manipulation MALLOC_NANO stays flat (512M→512M) vs unfixed (1.0G→1.5G), no crash.
* Note: requires re-downloading the zip (reinstall); not deliverable via in-app update (it touches the launcher and adds a dylib).
